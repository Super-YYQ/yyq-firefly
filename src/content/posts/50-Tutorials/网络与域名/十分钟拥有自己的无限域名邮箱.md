# 十分钟拥有自己的无限域名邮箱

本文整理自 [msdone 的 linux.do 原帖](https://linux.do/t/topic/927225)，保留原帖的收信、发信流程与配图。目标是：

- 用自己的域名接收多个地址的邮件，例如 `aa@example.com`、`bb@example.com`。
- 将邮件统一转发到 Gmail，再配置域名邮箱作为发件地址。
- 无需自行维护邮件服务器。

> [!info] 适用时间
> 本文于 2026-09-26 核对官方说明。Google 已宣布从 **2027 年 1 月**起停止 Gmail 对第三方邮箱地址的“用这个地址发送邮件”支持；Workspace 别名和其他本人 Gmail 地址不在该变更范围。下面保留原帖发信步骤，使用前先确认账号仍有此入口。Cloudflare 收信流程与该 Gmail 发信功能分开配置。见 [Gmail 官方说明](https://support.google.com/mail/answer/22370?hl=en)。

“无限”指 Catch-all 能接收未单独创建的地址前缀，不表示无限邮箱容量或无限发信账号。Gmail 的添加发件地址功能有数量限制，原教程也不能保证邮件一定进入对方收件箱。

## 为什么要这样做

原帖作者曾用网友分享的公共临时邮箱注册 Augment。换设备登录时，临时邮箱已经过期，无法再获取验证码，因此希望有一个可复用、自己能长期控制的邮箱地址。自己的域名加统一收件箱，可以避免依赖会失效的随机临时邮箱。

## 原理

[![域名邮件经 Cloudflare 转发到 Gmail，并通过 SMTP 发送的流程示意](https://cdn3.ldstatic.com/optimized/4X/d/c/d/dcd6e96517ee84ad8874789be629209f83af53c5_2_500x500.jpeg)](https://cdn3.ldstatic.com/original/4X/d/c/d/dcd6e96517ee84ad8874789be629209f83af53c5.jpeg)

用 Cloudflare 的“电子邮件路由”把域名邮件转发到 Gmail；发信则使用 Gmail 的“用这个地址发送邮件”功能和 SMTP。图中的发信协议应读作 **SMTP**。Email Routing 的收信配置本身不会给你创建一个 SMTP 发信账号。

## 准备

1. 一个自己持有、DNS 已托管到 Cloudflare 的域名；尚未接入时可先按《[[Squarespace域名迁移到Cloudflare完整教程|Squarespace 域名迁移到 Cloudflare 完整教程]]》操作。
2. 一个能管理该域名的 Cloudflare 账号。
3. 一个可接收验证邮件的 Gmail 账号；按原帖配置 Gmail SMTP 时还需要两步验证和应用专用密码。

下面正文使用 `example.com` 占位；截图中的域名来自原帖，操作时换成自己的域名。

## 一、开启 Cloudflare 电子邮件路由

这一步把收到的域名邮件转发到 Gmail。原帖参考了 [xiaohuang 的 Cloudflare 域名邮箱教程](https://linux.do/t/topic/316819)，本节配图也来自该帖，作者资料见 [xiaohuang](https://linux.do/u/xiaohuang) ![xiaohuang 的原帖头像](https://cdn3.ldstatic.com/original/3X/5/f/5f73437a37e8c41bee0b767973e01c640f869c4e.png?v=15)。

### 1. 打开 Email Routing

原帖从域名页面进入 **电子邮件（Email）→ 电子邮件路由（Email Routing）**，点击开始配置。新版官方文档的入口为 **Compute → Email Service → Email Routing**，先按向导添加自己的域名，再验证目标地址和创建规则。两种界面的收信目标相同，可对照 [Cloudflare 收信配置文档](https://developers.cloudflare.com/email-service/get-started/route-emails/)。

[![Cloudflare 域名控制台中的 Email Routing 入口](https://cdn3.ldstatic.com/optimized/4X/a/7/d/a7d614fcc835c0295aa2828458b8765450fb3bd6_2_690x369.png)](https://cdn3.ldstatic.com/original/4X/a/7/d/a7d614fcc835c0295aa2828458b8765450fb3bd6.png)

### 2. 创建地址并验证目标邮箱

先填一个域名地址，例如 `hello@example.com`，再填用于实际收件的 Gmail 地址。

[![创建域名地址并填写目标 Gmail 地址](https://cdn3.ldstatic.com/optimized/4X/1/4/0/14070cac6e5a4c77ebf9681d3c988ee6f4d4e1f9_2_655x499.png)](https://cdn3.ldstatic.com/original/4X/1/4/0/14070cac6e5a4c77ebf9681d3c988ee6f4d4e1f9.png)

目标邮箱尚未验证时会显示待验证状态：

[![目标邮箱等待验证](https://cdn3.ldstatic.com/optimized/4X/c/0/c/c0c03e387845aec494dbda7202e3bbedf9131a9e_2_690x323.png)](https://cdn3.ldstatic.com/original/4X/c/0/c/c0c03e387845aec494dbda7202e3bbedf9131a9e.png)

打开 Gmail 中的 Cloudflare 验证邮件，点击 **Verify email address**。没有收到时检查垃圾邮件文件夹，并确认填写的地址无误。

[![在目标邮箱打开 Cloudflare 验证邮件](https://cdn3.ldstatic.com/optimized/4X/1/5/4/154c9e7f44aeb9bfee6493053f532596ae8c204a_2_677x499.png)](https://cdn3.ldstatic.com/original/4X/1/5/4/154c9e7f44aeb9bfee6493053f532596ae8c204a.png)

验证成功后应出现确认页面：

[![目标邮箱验证成功](https://cdn3.ldstatic.com/optimized/4X/5/f/7/5f7ec64564ac49354086959ff63236a61c14c760_2_690x411.png)](https://cdn3.ldstatic.com/original/4X/5/f/7/5f7ec64564ac49354086959ff63236a61c14c760.png)

回到 Cloudflare 配置向导，继续下一步。

[![返回配置向导继续启用邮件路由](https://cdn3.ldstatic.com/optimized/4X/4/e/4/4e400b526591105b7b6f9aa86a33423406474f37_2_690x350.png)](https://cdn3.ldstatic.com/original/4X/4/e/4/4e400b526591105b7b6f9aa86a33423406474f37.png)

### 3. 配置邮件 DNS 记录

按控制台为当前域名列出的值添加 MX / TXT 记录，并启用路由；不要直接照抄截图中的值。若已有其他邮箱服务，先确认是否迁移收信服务，避免直接替换原 MX 造成旧邮箱断收；SPF 记录也要检查是否冲突。

[![添加 Cloudflare 要求的 MX 和 TXT 记录](https://cdn3.ldstatic.com/optimized/4X/4/b/4/4b460f6a7d161bdb7052a39c52b643c542101596_2_690x453.png)](https://cdn3.ldstatic.com/original/4X/4/b/4/4b460f6a7d161bdb7052a39c52b643c542101596.png)

### 4. 开启 Catch-all

在规则页面找到 Catch-all，启用后进入编辑：

[![启用 Catch-all 规则并进入编辑](https://cdn3.ldstatic.com/optimized/4X/d/4/b/d4b94f268e55de3277795b6b15f5c54719c35334_2_690x286.png)](https://cdn3.ldstatic.com/original/4X/d/4/b/d4b94f268e55de3277795b6b15f5c54719c35334.png)

动作选择 **发送到电子邮件（Send to an email）**，目标选择刚验证过的 Gmail，保存。

[![选择发送到已验证的目标邮箱](https://cdn3.ldstatic.com/optimized/4X/f/3/4/f34b5449f16bf3e9be3f99ee7d2a21fef13f809d_2_689x368.png)](https://cdn3.ldstatic.com/original/4X/f/3/4/f34b5449f16bf3e9be3f99ee7d2a21fef13f809d.png)

这样，未被其他专用规则匹配的 `任意前缀@example.com` 邮件就会转发到目标邮箱，无需逐个创建前缀。Catch-all 的匹配方式见 [Cloudflare 地址规则说明](https://developers.cloudflare.com/email-service/configuration/email-routing-addresses/)。

用另一个邮箱向 `test@example.com` 发一封邮件，确认 Gmail 收到后，再继续发信部分；如果失败，检查路由是否启用、目标邮箱是否已验证及 MX 是否生效。

## 二、开启 Gmail 的“用这个地址发送邮件”功能

这部分保留原帖通过 Gmail SMTP 发送域名邮件的做法。适用于账号仍支持第三方发件地址的时期；如果该入口已停用，需使用支持自己域名的邮件服务或 SMTP 服务及其客户端，不能靠重新设置 Cloudflare 收信规则恢复此功能。

### 1. 添加发件地址

打开 Gmail 设置，点击 **查看所有设置**。

[![打开 Gmail 的全部设置](https://cdn3.ldstatic.com/optimized/4X/4/f/8/4f8f2b42597a4ff9dadfa2d9b1ca9c349efb440e_2_184x500.png)](https://cdn3.ldstatic.com/original/4X/4/f/8/4f8f2b42597a4ff9dadfa2d9b1ca9c349efb440e.png)

进入 **账号和导入（Accounts and Import）→ 用这个地址发送邮件（Send mail as）→ 添加其他电子邮件地址**。

[![在账号和导入中添加其他发件地址](https://cdn3.ldstatic.com/optimized/4X/4/4/6/4466977220c1353ddeec4df073c09d4ba5fbbc3e_2_690x228.png)](https://cdn3.ldstatic.com/original/4X/4/4/6/4466977220c1353ddeec4df073c09d4ba5fbbc3e.png)

填写发件人显示名称和准备使用的域名邮箱，例如 `hello@example.com`。

[![填写发件人姓名和域名邮箱地址](https://cdn3.ldstatic.com/original/4X/2/a/b/2abf301704c2054b5b7ab507af2becb9c39926a5.png)](https://cdn3.ldstatic.com/original/4X/2/a/b/2abf301704c2054b5b7ab507af2becb9c39926a5.png)

### 2. 填写 SMTP 信息

原帖使用以下配置；用户名是自己的完整 Gmail 地址，密码是下一步创建的应用专用密码：

| 项目 | 填写内容 |
| --- | --- |
| SMTP 服务器 | `smtp.gmail.com` |
| 端口 | `587` |
| 安全连接 | TLS |
| 用户名 | 自己的完整 Gmail 地址 |
| 密码 | Google 生成的应用专用密码 |

[![填写 Gmail SMTP 服务器、端口和应用专用密码](https://cdn3.ldstatic.com/original/4X/4/6/1/461798e703ac10507f64563454a6efc4db296a0d.png)](https://cdn3.ldstatic.com/original/4X/4/6/1/461798e703ac10507f64563454a6efc4db296a0d.png)

### 3. 获取 App Password

1. 确认 Google 账号已经开启**两步验证（2-Step Verification）**，这是生成应用专用密码的前提。
2. 打开 [Google 应用专用密码页面](https://myaccount.google.com/apppasswords)，登录自己的账号。
3. 输入便于识别的名称，例如“域名邮箱发信”，创建密码。

[![为邮件发送创建应用专用密码](https://cdn3.ldstatic.com/original/4X/e/0/c/e0c3e6519eb0ef525bcff9aa972f4d3635dbb576.png)](https://cdn3.ldstatic.com/original/4X/e/0/c/e0c3e6519eb0ef525bcff9aa972f4d3635dbb576.png)

4. 复制生成的 **16 位密码**，填入 SMTP 密码框时去掉显示用的空格；不要使用 Google 账号登录密码。

[![复制生成的 16 位应用专用密码，原图已遮挡密码](https://cdn3.ldstatic.com/original/4X/0/5/9/059175e66cdfbe8777c80de9a1b4f929dfab5176.png)](https://cdn3.ldstatic.com/original/4X/0/5/9/059175e66cdfbe8777c80de9a1b4f929dfab5176.png)

5. 返回 Gmail 添加账号窗口，点击 **添加账号**。

若没有应用专用密码入口，可能与组织管理、仅使用安全密钥的两步验证或高级保护有关；修改 Google 主密码后，旧应用专用密码会撤销，需要重新生成。见 [Google 应用专用密码说明](https://support.google.com/accounts/answer/185833?hl=en)。

### 4. 验证发件地址并测试

Gmail 会向域名邮箱发送验证邮件。因为已经设置了 Cloudflare 转发，通常可以直接在目标 Gmail 中看到这封邮件，按邮件中的链接或验证码完成验证。

[![打开域名邮箱收到的 Gmail 验证邮件，原图已遮挡验证信息](https://cdn3.ldstatic.com/original/4X/9/e/6/9e6bdb27a76ad57f4179970ac4f195f1586e6dd5.png)](https://cdn3.ldstatic.com/original/4X/9/e/6/9e6bdb27a76ad57f4179970ac4f195f1586e6dd5.png)

验证后，新建邮件时选择刚添加的域名发件地址，向另一个邮箱发送测试邮件，再回复一次确认收发都通。如果要长期使用，还可分别设置默认发件地址和回复地址。部分收件客户端可能显示原 Gmail 地址或“代发”，并不保证隐藏原账号；具体行为见前面的 Gmail 官方说明。
